# Internal implementation contracts and ownership

All agents must obey the assigned directory boundaries. Root owns common/, all pom.xml files, backend DAO interfaces (excluding dao/jdbc), Bootstrap.java, Main.java, scripts/, README and external config examples. A owns database/, backend/config/ and backend/dao/jdbc/. B owns backend/service/ and backend/security/. C owns frontend/ui/. D owns all src/test/ and .github/workflows/. Report other-module defects to root; do not edit them. Do not commit or push individually.

## Assembly contracts
A implements DatabaseConfig(String url,String user,String password) with static load(), JdbcConnectionProvider(DatabaseConfig) implementing ConnectionProvider, JdbcUnitOfWork(ConnectionProvider) implementing UnitOfWork, and no-arg JdbcUserDao/JdbcCardDao/JdbcTransactionDao/JdbcStatisticsDao. JdbcUnitOfWork owns each connection, commit and rollback; DAO methods never open/close/commit their passed connection. read/write translate SQLException to BusinessException, duplicate constraint to DUPLICATE and other SQL problems to DATABASE_ERROR, retain cause. Transaction writes rollback runtime exceptions too. Set connection transaction timezone to +08:00.
B implements public ServiceFactory.create(UnitOfWork,UserDao,CardDao,TransactionDao,StatisticsDao) returning ApplicationServices. Authorization helpers must support checking a session and user on the same transaction connection. Registered token cannot be spoofed by modifying SessionContext fields. SQL connection errors preserve BusinessException codes. Seed hash format agreed PBKDF2WithHmacSHA256, 210000 iterations, 16-byte random salt, 32-byte derived key, encoded pbkdf2$210000$base64salt$base64hash. B provides public PasswordHasher.hash(char[]) / verify(char[],String).
C implements public com.campuscard.ui.login.LoginFrame(ApplicationServices). No calls to Bootstrap/config/JDBC. Root Main loads services, constructs LoginFrame on EDT, sets visible. All service calls off EDT including login/current user. C owns UI session generation/cancellation guards, parent disposal, amount form request-id lifetime and all navigation. On DATABASE_ERROR a write may have committed: preserve operation UUID and allow retry with same parameters, consult findOperation first. New request id only after confirmed success or explicit new form/reset. A failed operation lookup must not trigger blind new submission.

## Schema contract
users(id BIGINT PK AUTO_INCREMENT,username VARCHAR(50) unique,password_hash VARCHAR(255),full_name VARCHAR(100),student_no VARCHAR(30) nullable unique,role VARCHAR(10) USER/ADMIN,enabled BOOLEAN,created_at DATETIME(6)); campus_cards(id BIGINT PK AUTO_INCREMENT,user_id BIGINT unique FK users,card_no VARCHAR(32) unique,balance DECIMAL(12,2) nonnegative default 0); transaction_records(id BIGINT PK AUTO_INCREMENT,card_id BIGINT FK campus_cards,type VARCHAR(20) RECHARGE/CONSUMPTION,amount DECIMAL(12,2) positive,balance_before DECIMAL(12,2),balance_after DECIMAL(12,2),description VARCHAR(255),actor_id BIGINT FK users,operation_id VARCHAR(64) unique,created_at DATETIME(6)). InnoDB utf8mb4. Queries join users/cards to return TransactionRecord identity fields. Pagination 1-based, size 1..100, default 20 in UI. All timestamps Shanghai local time. Range dates inclusive via >=from midnight and <to+1 midnight; to before from rejected. Global user counts exclude ADMIN, balances include disabled USER cards; selected date range only affects transaction totals. Record ordering created_at desc,id desc. Schema idempotent CREATE TABLE IF NOT EXISTS, no DROP and no USE/database name in schema.sql; init scripts choose DB. Seed idempotent demo admin/admin123 and student/student123 with initial balance 100 represented by one recharge record, no destructive reset. Seeds must be explicit opt-in.

## Business rules
Validate positive money <=9999999999.99 with scale <=2 and post-recharge balance in range. No silent rounding. Lock users row before cards row in write transactions, including setEnabled. Disabled registered sessions denied. Admin create only USER with unique studentNo and zero balance card, atomic. Cannot edit/disable ADMIN from user-management API. currentUser must not disclose password hash. Validate usernames 3..50 [A-Za-z0-9_.-], password 8..128, trimmed fullName 1..100 and studentNo 1..30. Change password invalidates other user sessions, preserving current session. Operation id nonblank <=64; lock owning user/card before checking operation; existing operation must match owner, type, amount and description or reject OPERATION_CONFLICT. Successful duplicate returns original record. Consumer description 1..255, recharge default if blank. DAO reads do no authorization: B enforces it. User query with explicit other userId rejected; missing userId means current user for USER and all for ADMIN. findOperation never reveals other users. exportCsv returns BOM plus properly quoted CSV; neutralize spreadsheet formula characters in text columns.
